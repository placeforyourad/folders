# Техническое задание: Backend-сервис файлового дерева

## Цель

Разработать backend-сервер для управления древовидной структурой папок и файлов с использованием **PostgreSQL**.

---

## Правила структуры

- Существует корневой элемент `root`.
- `root` имеет тип `folder`, создаётся автоматически и **не может быть удалён**.
- Поддерживаются два типа элементов:
    - `folder` — папка;
    - `file` — файл.
- Папка может содержать файлы и другие папки.
- Файл не может содержать дочерние элементы.
- Структура должна возвращаться клиенту в виде дерева.

Пример:

```text
root
└── folder1
    ├── file1.txt
    └── folder2
```

---

## Хранение данных

Обязательно использовать **PostgreSQL**.

### Таблица `items`

| Поле         | Тип            | Описание                  |
| ------------ | -------------- | ------------------------- |
| `id`         | UUID           | Уникальный идентификатор  |
| `name`       | VARCHAR        | Имя файла или папки       |
| `type`       | VARCHAR        | Тип: `folder` или `file`  |
| `parent_id`  | UUID, nullable | ID родительского элемента |
| `created_at` | TIMESTAMP      | Дата создания             |

Для элемента `root` поле `parent_id` должно быть `NULL`.

## API

### 1. Получить дерево

```http
GET /api/tree
```

Возвращает полное дерево, начиная с `root`.

Пример ответа:

```json
{
    "id": "root-id",
    "name": "root",
    "type": "folder",
    "children": [
        {
            "id": "folder-id",
            "name": "folder1",
            "type": "folder",
            "children": [
                {
                    "id": "file-id",
                    "name": "file1.txt",
                    "type": "file"
                }
            ]
        }
    ]
}
```

У файлов поле `children` отсутствует.  
У пустых папок `children` равно `[]`.

---

### 2. Поиск по дереву

```http
GET /api/tree/search?query={строка}
```

Поиск выполняется по имени элемента:

- без учёта регистра;
- по частичному совпадению.

Результат поиска должен содержать **только путь от `root` до найденного элемента**, без соседних элементов.

Пример: при поиске `file1`:

```json
{
    "results": [
        {
            "id": "root-id",
            "name": "root",
            "type": "folder",
            "children": [
                {
                    "id": "folder-id",
                    "name": "folder1",
                    "type": "folder",
                    "children": [
                        {
                            "id": "file-id",
                            "name": "file1.txt",
                            "type": "file"
                        }
                    ]
                }
            ]
        }
    ]
}
```

Если ничего не найдено:

```json
{
    "results": []
}
```

---

### 3. Добавить файл или папку

```http
POST /api/items
```

Тело запроса:

```json
{
    "name": "new-folder",
    "type": "folder",
    "parentId": "folder-id"
}
```

Правила:

- `name` обязательно и не может быть пустым;
- `type` — только `folder` или `file`;
- родитель должен существовать;
- родитель должен быть папкой;
- нельзя создать элемент внутри файла.

Пример ответа:

```json
{
    "id": "new-id",
    "name": "new-folder",
    "type": "folder",
    "parentId": "folder-id"
}
```

---

### 4. Удалить файл или папку

```http
DELETE /api/items/{id}
```

Правила:

- `root` удалять нельзя;
- при удалении папки удаляется папка и всё её содержимое;
- при удалении файла удаляется только файл.

Пример ответа:

```json
{
    "message": "Item deleted successfully"
}
```

---

## Обработка ошибок

| Ситуация                        |       HTTP-статус |
| ------------------------------- | ----------------: |
| Некорректные данные запроса     | `400 Bad Request` |
| Родитель или элемент не найден  |   `404 Not Found` |
| Попытка добавить элемент в файл | `400 Bad Request` |
| Попытка удалить `root`          |   `403 Forbidden` |

---

## Дополнительные требования

- API работает с JSON.
- Данные должны храниться в PostgreSQL, без хранения структуры только в памяти.
- При старте приложения должен автоматически создаваться `root`, если его ещё нет.
- Код должен быть разделён минимум на маршруты, бизнес-логику и работу с БД.
